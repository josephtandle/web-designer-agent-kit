# Web Designer Agent Kit: Three Upgrade Loops

This document records the intended functional outcomes of three upgrade rounds. It is not a publication record or a claim that main-branch checks passed. Final assembled machine-readable acceptance evidence belongs in `docs/verification.json`, which the main integration lane will generate after relevant tests and observed checks.

## Round 1: Intake and design guidance

### Intended outcome

A participant can begin with a short brief, preserve existing context files, choose among distinct business-appropriate directions, and build with honest content.

### Included feature intent

- Discover installed skill references without assuming a fixed participant-project path.
- Ask at most 3 essential questions and recommend a direction based on audience, offer, and archetype.
- Preserve existing context and installed files by default.
- Provide a complete built-in SEO fallback: unique title and description, one meaningful H1, semantic navigation, crawlable text, approved Open Graph assets, verified-domain canonicals, and schema that matches visible facts.
- Keep forms honest: only connected endpoints with confirmed send intent count as working submission.
- Make original CSS and reduced-motion behavior the core motion path.
- Treat external skills and the GitHub catalog as optional research or acceleration, never core dependencies.

## Round 2: portable starter and preview

### Intended outcome

A first-time participant can download the kit, distinguish the kit root from the website project, install safely, create editable starter files, and open a local preview on macOS, Linux, or Windows.

### Included feature intent

- Require Node.js 24 or newer.
- Provide separate valid Bash and PowerShell setup, absolute `KIT_ROOT` and `PROJECT_ROOT` definitions, and quoted `--key=value` path arguments.
- Reuse an intended existing checkout and refuse overwrite assumptions.
- Run every script from the discovered kit root.
- Generate editable Service, Portfolio, and Event starter files without external runtime dependencies.
- Bind the preview server locally and protect hidden files, traversal routes, and symlink escapes.
- Call preview what it is: local preview, not publication.

## Round 3: integrated original design toolkit

### Intended outcome

A participant can choose a usable palette, explore distinct components and layouts, clean copy, and turn a visual reference into a working candidate through repeated evidence-led comparison.

### Included feature intent

- Palette Studio contract: 12 distinct palettes, paired light/dark themes, and 10 semantic export tokens including `border` and `onAccent`.
- Component Lab contract: 12 distinct layouts, 4 button treatments, 16 icons, and 3 optional effects.
- Reference Compare contract: side-by-side, overlay, and difference views aligned to one coordinate origin and scale.
- Reference workflow: observed-versus-inferred map, separate editable candidate directory, equal-state desktop/mobile capture, prioritized discrepancies, fixes, and repeated failed passes until no blocking mismatch remains or evidence runs out.
- Copy workflow: cleaning before visual QA, representative before/after examples, and a check that facts, evidence, and qualifications remain intact.
- Research catalog: reference material only in the default workflow, with no automatic external GitHub fetch.
- Ownership boundary: original kit code can be edited under the project terms; third-party assets and references remain subject to their own terms.

## Evidence status

This document describes accepted feature intention. It does not establish that the kit was published, deployed, or fully verified. Use `docs/acceptance.md` as the human-readable rubric and the final integration lane's `docs/verification.json` as assembled machine-readable evidence.
