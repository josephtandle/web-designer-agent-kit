# GitHub design research: an original, built-in toolkit

Reviewed 2026-09-12. This report records the research behind the Web Designer Agent Kit; it is not an installer or a dependency list. External projects were inspected for transferable principles, interaction coverage, and licensing boundaries. The kit’s normal build path remains offline and zero-dependency: it does not clone, import, vendor, or redistribute the repositories below. Any implementation in the kit must be independently written from the stated principle and tested against the kit’s own requirements.

“Original” below applies only to newly authored toolkit files. It does not relicense pre-existing repository content, participant media, fonts, screenshots, trademarks, or other assets. License identification is an engineering provenance aid, not legal advice.

## What the research produces

The useful outcome is a set of built-in tools, not a recommendation that participants assemble a stack of component libraries.

| Built-in surface | Current practical capability | Research translated into original implementation |
| --- | --- | --- |
| `tools/palette-studio.html` | Offline chooser with 12 starting palettes, a validated HEX seed, 9 semantic roles, light/dark editor views, component previews, measured foreground repair, and CSS/JSON export. | Semantic pair testing replaces “looks accessible.” Contrast uses the WCAG sRGB formula without rounding: the linearization breakpoint is `0.04045`, and a computed `4.499:1` fails a `4.5:1` target. It measures text/background, text/surface, action foregrounds, accents, and focus against their actual adjacent surfaces. |
| `tools/component-lab.html` and `references/layout-atlas.md` | Twelve genuinely different composition types: advisor landing page, case study, course overview, event agenda, product release, studio portfolio, service menu, editorial story, membership, nonprofit appeal, restaurant reservation, and single-CTA campaign. The lab also contains four action states, three restrained CSS effects, and 16 independently drawn geometric SVG icons. | Catalog breadth becomes content-led layout choice, responsive ratios, semantic controls, labelled icon buttons, stable pending/error/retry states, visible focus, and reduced-motion handling. No upstream block, icon path, or animation source is copied. |
| `scripts/reference-project.mjs`, `scripts/capture-reference.mjs`, `tools/reference-compare.html`, and `references/reference-layout.md` | Match-versus-Adapt setup; desktop/mobile evidence capture; side-by-side, overlay, and difference comparison; and three bounded passes: Structure, Type/Assets, Details. | The local WebFetch audit records useful evidence rather than private absolute paths: source/final URL, page title, HTTP status, timestamp, viewport, rendered capture, and sampled elements with title, tag, bounds, typography, and background details. Ordinary WebFetch did not provide that rendered element evidence; the capture path adds it. Screenshots remain evidence, never page backgrounds or automatic screenshot-to-code output. |
| `scripts/copy-check.mjs`, `references/copy-cleanup.md`, and `prompts/08-clean-website-copy.md` | A non-mutating automated check for six fixed text patterns, followed by broader manual Speak Human v3.1 review, protected-fact comparison, and optional manual revision. | Keeper-first editing preserves meaning and the participant’s explicit voice before applying requested tone or house guidance. The automated checker is limited to its six fixed patterns; the guide covers contextual review of clichés, prompt residue, inflation, empty contrasts, rhythm, and em dashes. Neither is an AI-authorship detector, and the checker does not rewrite code, attributes, quotations, claims, prices, names, dates, links, legal text, or SEO metadata. |

The palette tool is deliberately not a wrapper around the local `color-palette` RapidAPI product. That product is not the required interactive UI, and JPEG bytes are not treated as a pretend palette extraction algorithm. The kit instead offers an original chooser with visible semantic roles and measured theme pairs.

## Implementation and release boundaries

The sources are optional research material and are not needed for a normal build. A contributor should be able to create a site, choose a palette, inspect layouts/icons/states, compare reference evidence, and run copy review without network access or an upstream package. URL capture is the exception: it requires network access and a separately available browser runtime. It must record failures honestly and must never imply that a successful HTTP fetch proves visual or accessibility quality.

Reference recreation has two explicit modes. **Match** reproduces observed geometry using new participant content and assets. **Adapt** applies observed principles in a new structure. Both require semantic HTML, responsive behavior, original implementation, and separate checks for keyboard use, focus, contrast, long content, and reduced motion. Source HTML, CSS, scripts, fonts, logos, photography, and illustrations remain out of bounds unless the participant separately owns or licenses them.

No universal “all source code is free of licenses” claim is valid. New toolkit files have their own repository provenance; pre-existing files keep theirs, and participant/upstream assets may carry copyright, trademark, privacy, model-release, or contractual restrictions beyond a repository license. Likewise, this research does not establish a final quality score or prove every feature works in every browser. Release confidence must come from the kit’s own tests plus observed desktop/mobile, keyboard, contrast, export, capture-record, and failure-state checks.
